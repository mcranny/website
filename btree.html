B-Tree Storage Engine

Overview

This Rust key-value engine uses a fixed-page database file to examine insertion, deletion, and recovery without the additional layers of a SQL interface. Records pair a signed 64-bit key with up to 256 bytes of data. The implementation maintains tree structure and a persistent free list while using a checksummed redo log to recover interrupted page updates.

Source repository

Page organization

Every database page occupies 4,096 bytes, with integers encoded explicitly in little-endian order. Page zero stores the file metadata; subsequent pages contain either tree nodes or free-list entries. A bounded 64-page LRU cache holds recently used pages, so the in-memory working set is separate from the total size of the file.

Database page types
Metadata File identity and format version, root page, page count, and free-list head
Node Leaf or internal type, parent and key count, thirteen fixed-width records, and fourteen child page references
Reusable page Free-page identity and reference to the next free page

Write recovery

A put or delete operation records the changed page images in a redo log before updating the database file. In the default durability mode, the engine synchronizes the log before checkpointing dirty pages and clears it after the page writes have been synchronized. On reopening, a complete log record can therefore be replayed to restore the intended page images.

The API also provides a deferred mode for bulk workloads whose durability boundary is a successful close. The engine supports one writer; multi-operation transactions, locking, and concurrent access are outside its current scope.

Correctness testing

Generated sequences of insertions and deletions exercise splits, merges, and root contraction. After relevant operations, point lookups and inclusive range scans are compared with an in-memory reference and a live SQLite table. Property-based tests shrink failing sequences, making a discrepancy easier to reduce to the operation that violates an invariant.

Separate checks examine key ordering, parent pointers, close/reopen persistence, and reuse of freed pages. Recovery tests distinguish complete log records from truncated or corrupt records. The CI workflow runs formatting checks, Clippy, and tests with all targets and features enabled.
