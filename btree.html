B-Tree Storage Engine

A small database with recoverable writes.

Rust key-value storage with a checksummed redo log. Tests run the same operations against SQLite and compare the results.

View sourceView all projects

Inside the database file

Each page holds 4,096 bytes. Records pair a signed 64-bit key with up to 256 bytes of data, and a 64-page LRU cache keeps recently used pages in memory.

Recovering an interrupted write

Before changing the database file, the engine writes the updated page images to a redo log and synchronizes it. The log is cleared only after those pages have been written and synchronized.

On restart, a complete log record is replayed. Truncated records and checksum mismatches have separate recovery tests. The engine uses a single writer with a close and checkpoint step.

Compared with SQLite

Generated operation traces exercise insertion and deletion, including splits and merges. Point lookups and full range scans are compared with an in-memory SQLite table after each relevant operation.

Structural checks verify key ordering and parent pointers. Reopen tests check that merged pages return to the free list and can be reused.
