How the plan is built

The desktop application searches departure dates and travel times. Each result must reproduce the arrival state in a separate propagation check before it reaches this viewer.

Data JPL close-approach records identify candidates, while orbital elements provide the state needed for trajectory search and display.
Storage Normalized records and uniqueness constraints make repeated updates deterministic and keep source observations separate from derived plans.
Search A universal-variable Lambert solver evaluates configurable departure and arrival windows instead of relying on a single hand-picked trajectory.
Validation Endpoint propagation checks must reproduce the required arrival state before a plan is retained for inspection.
