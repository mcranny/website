Protocols are firmware running on a common timing engine. V2 extends that foundation to receiving data, coordinating two engines, and recording what happened at the interface.

01 · Execute

Generate and respond

UART transmit and receive, all four SPI modes, and I²C at 100 or 400 kHz. SPI and I²C examples cover both controller and target roles.

02 · Observe

Capture the context

Each engine has 16-byte TX and 16-record RX queues. A separate 32-record capture unit records synchronized pin activity, including glitches rejected by the engine input filter.

03 · Reproduce

Make failures repeatable

Python assembly and loading tools, a cycle model, independent protocol observers, and retained test evidence connect intended behavior to implementation.

Operation and next steps

Use the V2 Python APIs to configure the engines, load programs, and read results. Program and capture storage are volatile, so reset, reconfigure, and reload after state loss. The 1 Mbaud duplex examples run preloaded bursts; sustained operation is limited by the 1 MHz SPI host service rate. The installed CLI supports V1.

Next steps include expanded RTL properties, review of compositional assumptions, broader mutation testing, and a Lean ISA model. Verification roadmap →

From V1 to V2

More capability in the same 6 × 4 footprint. V1 established programmable transmission and completed electrical closure. V2 adds independent execution, receive paths, and capture.
