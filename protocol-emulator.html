Programmable Protocol Emulator ASIC

Design, implementation, and verification of a dual-engine ASIC for programmable digital interfaces.

The ASIC generates and records protocol traffic using two programmable engines, deadline-driven pins, and timestamped capture. This case study documents the V2 and V3 designs, their verification results, and FPGA operation. The Verilog and Python implementation was developed for Jane Street’s Protocol Emulator ASIC Competition.

V2 and V3 design comparison

V2 established two independent engines, receive queues, and triggered capture. V3 moves program storage into SRAM and gives each pin its own deadline, so firmware can compute the next action while the hardware keeps time.

V3 execution and timing architecture

Each engine advances a private time cursor and schedules output values and enables. The pin cells apply those changes on the shared clock, keeping edge timing consistent across branches and concurrent programs.

Running on Artix-7

Ran V3 at 48 MHz on a Digilent Cmod A7-35T, loaded and executed programs through the host bridge, and captured a 25 kHz output in Vivado ILA.

Board integration

Cmod A7-35T

A 12 MHz board oscillator feeds the 48 MHz core clock. FPGA block RAM holds the two programs, and a USB-UART bridge carries host commands to the SPI interface.

Program execution

Host loading and execution

The host writes the program image, reads it back, configures pin ownership, and starts the engine. The programmed output runs on the board.

V2 execution, receive paths, and capture

Protocols are firmware running on a common timing engine. V2 extends that foundation to receiving data, coordinating two engines, and recording what happened at the interface.

01 · Execute

Protocol transmission and reception

UART transmit and receive, all four SPI modes, and I²C at 100 or 400 kHz. SPI and I²C examples cover both controller and target roles.

02 · Observe

Queues and timestamped capture

Each engine has 16-byte TX and 16-record RX queues. A separate 32-record capture unit records synchronized pin activity, including glitches rejected by the engine input filter.

03 · Reproduce

Verification and reproduction

Python assembly and loading tools, a cycle model, independent protocol observers, and retained test evidence connect intended behavior to implementation.
